# 规则分类与执行时机

## 当前设计与实现

`src/categories.ts`、`src/apps/`、`src/globalGroups.ts` 和 `src/subscription.ts` 已按本设计配置。当前源码包括 670 个应用、1,753 个应用规则组及 3 个全局规则组；`dist/` 和 README 发布统计仍以最近构建为准。推送运行检查，源码变化随每周三北京时间 03:20 的定时构建发布。

GKD 根据应用规则组的名称前缀归类，下列 10 类均为独立类别，不另设“限时”“持续”父类别。

同一应用内的规则组名称须唯一；同场景同时有直接关闭和多步关闭规则时，多步组使用“分步关闭”后缀区分，仍同属页面内广告类别。

| 类别                | key | 应用规则组数 | 内容                                             |
| ------------------- | --- | ------------ | ------------------------------------------------ |
| 限时-开屏广告       | 12  | 121          | 进入应用时的开屏广告                             |
| 限时-全屏广告       | 13  | 189          | 按启动窗口处理的全屏广告                         |
| 限时-应用提示       | 14  | 317          | 启动窗口内的升级、通知、评价、兴趣及其他应用提示 |
| 持续-小程序开屏广告 | 15  | 3            | 使用过程中打开小程序时出现的广告                 |
| 持续-全屏广告       | 16  | 241          | 使用过程中出现的全屏广告，含延后或重复出现的开屏 |
| 持续-页面内广告     | 17  | 408          | 横幅、浮层、卡片及需要多步关闭的页面内广告       |

## 时间和匹配边界

- **限时：627 组。** 统一为 `matchTime: 20000`、`resetMatch: 'app'`，规则级覆盖参数也使用相同时限。进入应用后最多匹配 20 秒，应用内切换页面不重新计时；原有次数等条件仍可使规则提前停止。
- **持续：1,106 组。** 使用过程中仍有机会匹配，保留必要的页面窗口、次数、冷却和页面限制。含启动与内部页面的混合组归持续，其中只处理启动场景的子规则仍可保留自身短时窗口。持续不表示强制轮询。
- **系统权限：20 组。** 按实际处理内容归类，保留时间和执行参数。业务应用自己的通知、定位等引导仍归应用提示；不把系统应用中的全部功能都归为权限。
- 原有选择器、节点查询方式、点击动作、500 毫秒等点击延迟、强制查询时长、共享冷却和次数、规则衔接、快照及图片链接保留。

启动归属根据现有匹配界面、规则约束和已知场景判断，不代表所有规则都已在设备上重新验证。明确包含深层页面或重复触发的规则不加应用启动截止；没有启动依据的无时限规则保持持续。

## 默认开关

10 个类别均不设置统一 `enable`，跟随各组默认值。应用规则默认开启 127 组、关闭 1,626 组；系统权限默认保持关闭。默认开启的 127 组包括 121 组限时开屏、3 组小程序开屏和 3 组持续开屏。

类别 key 使用 12—21，不沿用语义不同的旧类别标识。更新订阅后须重新检查分类开关；应用 ID、规则组 key 和规则 key 保持稳定，按规则组保存的配置仍有对应标识。

## 全局规则与专用规则避让

3 个全局规则不属于应用分类，独立保留开关及规则组 key。全局开屏、升级提示、青少年模式均采用进入应用后 20 秒的匹配窗口，原有强制查询、次数、冷却和防误触条件保持不变。

`disableIfAppGroupMatch` 只支持单个名称前缀，而同一用途现在分布在限时、持续类别。`src/subscription.ts` 按当前用途前缀查找专用规则，将对应应用合入全局规则的禁用配置；跳过 `ignoreGlobalGroupMatch: true` 的专用组，不受专用组启用状态影响。各用途前缀如下：

- 开屏：`限时-开屏广告`、`持续-小程序开屏广告`、`持续-全屏广告-开屏广告`。
- 升级：`限时-应用提示-更新提示`、`持续-更新提示`。
- 青少年：`限时-应用提示-青少年模式`、`持续-应用提示弹窗-青少年模式`。

专用开屏组继续使用 `OPEN_AD_ORDER` 优先级。全局规则原有应用保护名单、白名单及条件仍由 `src/globalDefaultApps.ts` 维护；专用规则避让会覆盖同一应用的全局默认开启配置。新增或改名涉及这些用途的组时，应同时核对避让与优先级。
