# 当前维护规则与任务

## 实际实现

- 维护仓库为 `yanmuq/GKD_subscription_yan`，订阅 ID 为 `666`，用于替换原 AIsouler 订阅地址。附加订阅 `yanmuq/muqi_gkd` 的 ID 为 `808`，两者独立。
- 当前维护的应用集合由 `src/apps/` 决定；`dist/` 和 README 统计区为最近发布产物，未构建的源码调整将在固定发布时合入。精简时保留未选应用原有规则及附加订阅覆盖的应用。
- 开发依赖使用 `@gkd-kit/api 0.9.3`、`@gkd-kit/tools 0.8.0`、`@gkd-kit/define 0.0.1`。API 类型中的废弃版本数组字段未用于当前规则；不为“换新写法”引入无用途的版本限制。
- 默认只开启“开屏广告”类别。全局开屏、更新提示和青少年模式规则已有 10 秒匹配时限与按应用重置；全局开屏保留 10 秒强制查询，以覆盖没有事件通知的跳过按钮。
- 云闪付 6 个规则组共 8 条应用规则使用 500 毫秒 `actionDelay` 与 `clickCenter`。延迟后仍需重新匹配才执行；保留浮动按钮已有的坐标偏移。
- `fastQuery`、`matchRoot`、`forcedTime`、`priorityTime` 及共享冷却/次数参数仍是有效 API。它们是否需要调整取决于具体界面，不能按字段年代统一删改。
- 两个订阅间不共享冷却与点击次数。相同应用的相同用途规则只在一个订阅中启用，避免重复执行。
- 构建只处理当前订阅、版本索引、规则清单及 README 统计；相同内容保持版本，内容改变时递增版本。推送运行检查，每周三北京时间 03:20 检查构建输入，有变动才构建。

## 查询优化边界

- 删除不使用的应用规则主要减少订阅体积与维护范围，不能据此推算日常耗电降低比例；查询耗时仍取决于当前前台应用及启用规则。
- 快速查询要求选择器位置正确且节点可快速查找，查询顺序可能与普通遍历不同。任何重排都必须用对应快照比较命中节点，不能仅依据布尔条件等价。
- 北京一卡通组 1 的 `not_prompt_again` ID 位于首个属性条件，使用快速查询直接定位目标；[对应快照](https://i.gkd.li/i/19718306) 的目标节点支持 ID 快查，原有截图链接仍保留。
- 云闪付组 15、高德组 13 的规则 2/3 及组 14 的规则 2，目标文本节点不支持文本快查。保留现有容器 ID 快查与内部遍历，不把文本条件移到首位。
- 微信组 9 和一刻相册组 0 的慢查分支用于无法快速查询的节点，保留。
- 全局开屏规则包含描述、正则和 ID 后缀匹配的通用回退；排除误触条件及应用保护名单必须保留。
- 仅确认属于应用启动阶段的弹窗采用 `matchTime: 10000`、`resetMatch: 'app'`、`actionMaximum: 1`。页面内反复出现的弹窗不能套用启动时限。
